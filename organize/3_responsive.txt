[base]
  > 반응형 (responive): 적응형(Adaptive) 이후 단계로 장치의 변화나 화면 크기의 변화에 따라 내부 Layout요소들이 변경 및 조정 되는 것
    - 적응형은 장치를 넘나들 수 없지만 반응형은 가능하며, 적응형은 조정만 가능데 반응형은 좌중우 상중하 변경 가능
    - 반응형의 두 가지 종류
      1. 장치상 반응형(deviceControl responsive): 장치의 접근을 통한 식별부호 (S/N, M/N, MAC Addr..)를 이용하여 개별 file들을 장착시키는 반응 형태
        + 삼성, 애플 등의 전 기종을 다 다뤄야 하므로 어려운 작업(실무에서 만날 가능성 희박)
      2. 화면상 반응형 (Resolution responsive): 출력되는 장치(모니터, 빔, 스마트폰, 태블릿)의 화면크기(Viewport)를 측정하고 이를 이용하여 분리된 source를 적용하는 반응형태
        + 보통 반응형이라고 하면 화면상 반응형을 일컬음. 장치가 무엇이든 해상도 개념이 가장 중요
      + 두 반응형의 차이점이라고 하면 파일 자체가 분리되느냐(장치상), 파일 안에서 분리되느냐(화면상)의 차이
      + etc. 이와 별개로 장치별 구현방식이 있으나 이 방법은 현재는 많이 사용되지 아니함(ex> m.naver.com <->naver.com m은 mobile을 뜻함)

[step_1]

  > 장치상 반응형(deviceControl responsive)
    - screen / print : 미디어 쿼리에서 사용하는 용어로, 웹페이지가 어떻게 표시될지 기기의 종류에 따라 스타일을 다르게 적용하는 방법을 말함
    - screen: 웹페이지가 모니터, 스마트폰, 태블릿 같은 디지털 화면에 표시될 때 사용하는 스타일을 적용하는 방식 
      + 빛으로 색을 표현: 가산혼합(RGB) 사용
    - print: 웹페이지가 프린터로 출력될 때 사용할 스타일을 정의하는 방법. (Ctrl + P로 확인 가능)
      + 잉크로 색을 표현: 감산혼합(CMY/CMYK) 사용
    - main page file명은 꼭 index.html로 지정해야함
      + 브라우저가 index로 자동 인식하기 때문. 다른 이름으로 지정하게 되면 back쪽에서 server redirect라는 불필요한 작업이 필요해짐
    - 1280px로 가이드를 잡고 작업해야 함
    - svg icon을 당길 때는 기존 px 두 배 크기로 받는 것이 안전함(dpi 개념)

[step_2]

  > 화면상 반응형(Resolution responsive)
    - <meta>: HTML 문서의 <head> 영역에서 사용되어 webpage에 대한 metadata를 제공하는 tag. 
      + metadate는 페이지 자체의 정보나 설명, 키워드, 작성자, 뷰포트 설정 등 다양한 정보를 포함할 수 있으며, 검색 엔진 최적화(SEO)나 소셜미디어 공유 시 중요한 역할을 함 
      + 반응형 페이지에는 viewport를 추가 하여, content 사이즈에 대한 유동폭을 선언 해줘야함
        - width=device-width: default 장치의 너비와 동기화(width=240 이면 240px 고정). height 역시 마찬가지
        - initial-scale=1.0: 초기 확대 비율(백분율)
        - user-scalable=no: 확대 및 축소 가능 여부. default가 yes라서 잘 사용하지 않지만 확대할 경우 float가 무너지는 걸 방지하기 위해 no를 사용할 때가 있음
        - minimum/maximum-scale: 최소 축소 비율 / 최대 확대 비율. user-scalable을 사용하지 않고 float가 떨어지지 않을 만큼만 비율 설정 가능
        - target-densitydpi: dpi 지정. 
          + dpi(dots per Inch): 화면의 픽셀 밀도를 의미
        - 이외 추가적인 viewport 메타는 운영체제 별 참고
          + Android : http://developer.android.com/guide/webapps/targeting.html
          + IOS : http://developer.apple.com/library/safari/#documentation/appleapplications/reference/safarihtmlref/Articles/MetaTags.html
    - css 작업 setting 순서
      + @import url('font url'); - 절대적 우선. 직접 작성하는 것이 아닌 webfont, icon, plugin등 외부에서 불러와야하는 css 입력. 먼저 작성하지 않으면 우리가 작성한 것들이 씹힘
      + @import url('reset.css'); - 첫번째. 레이아웃 구성 시 방해가 될만한 것들을 제거해둔 code이며 앞으로 내가 하는 모든 작업에서 필수
      + @import url('module.css'); - 모듈링을 할 수 있을 때
      + @import url('global.css'); - 두번째. header, footer와 같은 공통 사용 영역
      + @import url('page.css'); - 세번째. 별도로 사용하는 나머지들(하나의 파일 안에서 전부 작업)
    - 미디어 쿼리(Media Query): 웹 개발에서 디바이스의 화면 크기나 해상도에 따라 다른 스타일을 적용할 수 있게 해주는 CSS 기술
      + 지원 디바이스가 다양하나, 미디어쿼리의 조건이나 속성들이 브라우저마다 다르게 해석되거나 지원 범위가 다를 수 있기 때문에 사용 전 브라우저 지원 여부를 확인해야 함
      + 사용 방법
        A. html <head> 에 <link rel="stylesheet" type="text/css" href="" media="screen" />
        B. @import url() screen; 
        C. @media screen and (min-width:768px)

  - Desktop > Tablet > Mobile 순서로 작업하며 위로 쌓이는 구조로 code 작성
    + Desktop code에서 조금씩 수정하며 쌓아가는 구조이기 때문에 desktop code를 신경써서 작성해야 함
  - 범위 설정(각 나라마다 기준 상이할 수 있음. 한국 기준: -1px하면 됨)
    + Desktop: (min-width: 1280px) ~
      > Desktop의 min-width는 1280px으로 현존하는 가장 작은 모니터까지를 취급하며, max-width는 함부로 걸 수 없음(웹 접근성)
    + Tablet: (min-width: 768px) ~ (max-width:1279px)
      > 해상도 스펙트럼이 넓기 때문에 현재 테블릿이 가장 큰 이슈!
    + Mobile: ~ (max-width: 767px)
  - and: Media Query의 조건부사. 조건을 확장해서 사용할 수 있음
      + 조건부
        - if문: if(조건부)
        - switch문: case(조건부)
  - 오리엔테이션: 디바이스 화면의 방향을 의미(시뮬레이터: f12 toggle device)
    + 세로 portrait / 가로 landscape
  - 가장 작은 해상도의 스마트폰, 테블릿 장치는 구비하는 게 좋음
